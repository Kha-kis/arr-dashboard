# 3.0 UI/UX Modernization

## Decision

The 3.0 release includes a cohesive web UI/UX modernization. This is a product
requirement in addition to the completed charter deliverables, not a cosmetic
cleanup after release. The meaningful 3.0 soak begins only after the final
modernization slice is merged to `next`.

The work preserves the existing domain behavior, API contracts, data ownership,
and accessibility/security guarantees. It deliberately avoids a one-shot
rewrite: each slice must be independently usable, browser-verified, and
releasable.

## Audit baseline

The live web router has 23 page routes, with 21 operational destinations in the
sidebar. The current shell establishes useful feature groupings, but the product
experience is fragmented by competing page-header, container, table, tab, and
empty-state primitives. Individual feature clients also vary widely in density,
action placement, loading behavior, and mobile treatment.

Existing foundations to retain and consolidate:

- semantic, brand, and user-theme color systems;
- Satoshi display and DM Sans body typography;
- incognito-mode redaction and service-availability semantics;
- React Query, centralized query keys, and polling contracts;
- shared accessibility-aware Radix primitives and semantic z-index layers;
- the command palette, responsive sidebar, and real-time qui invalidation.

## Experience contract

The finished product must make the following consistently true:

1. **Operate before configure.** Attention, current system state, and safe
   next actions lead the experience; configuration is available without
   competing with operational work.
2. **One page anatomy.** Every authenticated route has a clear title/context,
   primary action, compact secondary controls, consistent content-width and
   spacing rules, and intentional loading, empty, error, and permission states.
3. **Predictable navigation.** The shell distinguishes Now, Media, Automation,
   and Configure/maintain work; it remains usable at tablet and phone widths
   without hiding active context.
4. **Information-dense, not crowded.** Tables, cards, filters, and drawers use
   the same density scale and reveal detail progressively instead of rendering
   every control at once.
5. **Trust stays visible.** Incognito behavior, freshness, service health,
   destructive-action friction, and unavailable-service explanations remain
   correct in every redesigned surface.
6. **Accessible by default.** Keyboard navigation, visible focus, semantic
   labels, contrast, reduced-motion behavior, and touch targets are acceptance
   criteria, not post-polish.

## Delivery slices

| Slice | Scope | Exit criteria |
|---|---|---|
| UX-1 Shell and foundations | Navigation IA, top bar, responsive chrome, unified page anatomy, density/spacing/state primitives | Browser-verified desktop/tablet/mobile shell; keyboard and focus pass; no route loses active context |
| UX-2 Daily operations | Dashboard, Console, Pulse, calendar, statistics, qui home/activity | Attention-first hierarchy; shared states/actions; live data and incognito behavior verified |
| UX-3 Media workflows | Discover, requests, search, library, history | Consistent browse-to-detail flow, filters, tables/cards, and responsive drill-downs |
| UX-4 Automation and maintenance | Hunting, queue/library cleanup, auto-tag, label sync, cross-seed, indexers, TRaSH | Consistent configuration-to-run-history flow; destructive and deploy actions remain explicit |
| UX-5 Setup, settings, and authentication | Setup, login, account/security, service and system settings | First-run and security flows are coherent with the new shell; auth regressions covered |
| UX-6 Integration and polish | Cross-route consistency, performance, accessibility, documentation, visual regression coverage | Full browser/responsive/a11y review, production build/E2E, and independent code review pass |

## Release gates added by this decision

Before rc.1, all six UX slices must be merged to `next`, browser-verified using
representative configured and unconfigured states, and pass the full repository
verification gauntlet. The final slice establishes the new beta baseline; the
two-week no-major-regressions soak starts from that merge rather than the prior
2026-07-15 baseline.

## Non-goals

- Changing backend APIs or stored data solely for presentation.
- Replacing the user-selectable theme system with hard-coded branding.
- Removing incognito mode, freshness, health, or confirmation behavior for a
  cleaner appearance.
- Large undifferentiated refactors that make visual regressions impossible to
  isolate.
